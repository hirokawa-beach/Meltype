# 郵便番号から住所への変換

日本郵便の全国 UTF-8 一般住所データをアプリに埋め込み、Windows・macOS・Linux 共通の Core で検索します。入力を外部サービスへ送信せず、オフラインで使えます。

## 入力と設定

Windows の動作モードが「Meltype IME」の場合は、試す入力欄で Win＋Space を押し「Meltype IME」を選んで、日本語入力にしてください。

`1000001` または `100-0001` を入力して Space を押すと、番号を先頭に残して住所候補を出します。Space / ↓ や候補番号で選び、Enter で確定できます。入力中の Enter は番号をそのまま確定し、Esc は元の入力に戻します。Tab 変換も従来の設定に従います。英語の文脈では Space は確定＋空白、Shift+Space / 変換キーは明示変換です。

Windows の既存設定画面の「1. 全般」に、次の ON/OFF を配置しています。

| 項目 | 初期値 | 例 |
| --- | --- | --- |
| 郵便番号: 基本住所の候補 | ON | 京都府京都市上京区北町 |
| 郵便番号: 通り名＋町名の候補 | OFF | 京都府京都市上京区上の下立売通天神道西入上る北町 |
| 郵便番号: 通り名のみの候補 | OFF | 京都府京都市上京区上の下立売通天神道西入上る |
| 郵便番号: 小字込みの候補 | ON | 福島県耶麻郡北塩原村桧原秋元 (`9692701`) |

複数の通り名は個別に生成します。小字を有効にした番号では小字の候補だけを出し、その行の大字までの候補は出しません。その他の住所と通り名は従来どおりです。4 種類をすべて OFF にしても、登録番号については番号と全角番号の候補を残し、外部変換エンジンの住所候補は混ぜません。設定はプロファイルにも保存され、Windows では次の変換から反映します。

macOS・Linux は既存の `config.json` に同じ設定を保存します。データフォルダーは既存のメニュー・案内から開けます。設定変更後は入力サービスを再起動してください。これらの OS には既存の Windows と同じ設定画面がないため、新しい専用 UI は追加していません。

```json
{
  "PostalBasicAddressCandidates": true,
  "PostalStreetAndTownCandidates": false,
  "PostalStreetCandidates": false,
  "PostalKoazaCandidates": true,
  "PostalFloorNumbers": "FullWidth"
}
```

上記は設定項目の抜粋です。既存の設定ファイル全体を置き換えず、該当項目を追加・編集します。

## 原文・条件の扱い

- 通常の町域は従来どおりの住所にします。
- 「以下に掲載がない場合」「市区町村の次に番地がくる場合」「一円」は市区町村までの住所と注記に分けます。原文は辞書に残します。
- 京都市の通り名は、末尾の単一括弧の列挙と方向表現・終端を検査できる場合だけ分離します。各通り名に「町名との結合可否」を保存し、方角で終わる一部表記などは通り名のみ生成します。未認識の項目が混じる場合は部分展開せず原文を保持します。
- 丁目・番地・地割・号などを明記した単純な数値範囲、単純な数値による除外・限定条件、「その他」は基本住所と注記に分けます。
- ビルの末尾の数値階・「地階・階層不明」を、同じ市区町村の登録町域に照合して分離します。町域と建物名の間に半角空白を入れ、数値階は括弧を外します。地階・階層不明は建物名までにします。未知の階表記や照合できない建物は原文保持です。
- 「次のビルを除く」は町名から分離し、詳細に保存します。
- 南／北などの町域名、解釈できない小字の列挙、入れ子の説明、単位が不明な数字の列挙、地名を含む複雑な範囲などは原文のまま候補にします。

条件がある候補には短い注記を表示し、選んで少し止まると町域原文を詳細欄に出します。郵便番号の条件は通常の「候補の意味を表示」を OFF にしても確認できます。同じ挿入住所になる行は重複をまとめますが、原文・条件はすべて詳細欄に結合します。郵便番号が違う行はまとめません。

検索は未確定入力全体が半角 7 桁または `3 桁-4 桁` の場合に限定します。直接入力・かな入力の数字打鍵・URL 等の保護区間は対象外です。任意の文字や空白を除去して番号にしたり、郵便番号から番地・建物名を推測したりしません。事業所個別番号、逆引き、旧町名・表記揺れの補正は未対応です。

郵便番号候補の選択は、変換履歴・言語学習・予測学習・外部エンジンの学習に保存しません。通常の確定・診断ログの設定は従来どおりです。

## 大字・小字

小字込みの候補は初期ONです。`9692701`は「福島県耶麻郡北塩原村桧原秋元」など17個の小字だけを出し、大字・町域までの候補は出しません。「郵便番号: 小字込みの候補」をOFFにすれば従来の大字までの候補になります。原文にない「大字」「字」は補いません。元の郵便番号は先頭に残します。

| 番号 | 初期設定の最初の住所候補 |
| --- | --- |
| 9790622 | 福島県双葉郡富岡町毛萱前川原 |
| 3703311 | 群馬県吾妻郡東吾妻町岡崎烏帽子 榛名湖畔 |
| 3703321 | 群馬県吾妻郡東吾妻町泉沢烏帽子 榛名湖畔 |
| 3703322 | 群馬県吾妻郡東吾妻町川戸烏帽子 榛名湖畔 |

小字名に付いた数字・番地・数値範囲は候補へ挿入しません。名前のない数字だけの続きも飛ばします。半角`[]`、全角`［］`、亀甲括弧`〔〕`内は挿入しません。`「榛名湖畔」`のような名前付き引用は、括弧を外して前の名前と半角空白でつなぎます。数字を含む引用の番地・除外条件は原文詳細だけに保持します。条件を解釈できない場合は、部分展開せず従来の条件処理または原文保持にします。

元CSVの11列目「小字毎に番地が起番されている町域」のフラグが1の行を手掛かりにします。`3703311`のフラグは0ですが、名前に付いた数値条件でない引用を確認できる場合は同じ整形を適用します。`3703321`の「烏帽子国有林７７林班」も別の候補として出します。国有林に明記された「７７林班」「第２８班」の番号・単位は番地省略の対象から外し、原文どおり残します。フラグが0でも、この形式を確認できる列挙は分離します。フラグは括弧内の意味を保証しないため、読み仮名・同名大字の区別・単一方角・未知の説明は連結しません。行政上の大字・小字や通称の厳密な意味を推測して変更するものではありません。

候補の詳細には、省いた数字・括弧を含む町域原文をすべて保持します。同じ大字でも郵便番号が違う小字は混ぜません。基本住所のON/OFFにかかわらず、小字込みONでは分離できた行の小字だけを出します。OFFでは基本住所の設定に従って大字までを出します。小字の設定は通常住所・京都・建物の候補には影響しません。

## 建物・階別番号

| 番号 | 初期設定での候補 |
| --- | --- |
| 1006090 | 東京都千代田区霞が関 霞が関ビル |
| 1006036 | 東京都千代田区霞が関 霞が関ビル３６階 |
| 1000013 | 東京都千代田区霞が関 |
| 1006890 | 東京都千代田区大手町 JAビル |
| 1416001 | 東京都品川区大崎 ThinkParkTower１階 |

「郵便番号: 階数の数字」で **全角 (３６階)** / **半角 (36階)** を選べます。初期値は全角です。JSON は `PostalFloorNumbers: "FullWidth"` / `"HalfWidth"`。階数の変更は町域・建物名の数字に影響しません。英字を含む建物名の全角 ASCII 英数字・記号は半角へ変換し、日本語・カナ・ローマ数字は保持します。英字のない建物名の数字（例: サンシャイン６０）は原文どおりです。

「地階・階層不明」は地下階を含む日本郵便の区分です。特定の地下階を推測せず、建物名まで出し、注記と町域原文に区分を保持します。複数の登録町域が接頭辞になる場合（天満 / 天満橋）は最長の町域を採用します。ビル名だけで照合せず、都道府県・市区町村も一致させます。

## 保存形式と生成

`dictionaries/postal-codes.tsv.gz` は schema 4 の gzip 圧縮 UTF-8 TSV です。各行は次の 8 列です。

1. 7 桁の郵便番号
2. 都道府県＋市区町村
3. 町域原文（変更しない）
4. 分類
5. 安全に分離できた町名（分離しない場合は空）
6. 通り名と町名結合可否の JSON 配列（通り名がない場合は空）
7. 建物の町域・建物名・半角階数の JSON 配列（建物を安全に分離できない場合は空）
8. 小字の JSON 配列（小字を安全に分離できない場合は空）

元の住所を保存し、設定に応じた文字列は検索時に生成します。gzip 本体は Core の埋め込みリソースです。起動時に UTF-8 本体と検索索引をバックグラウンドで準備し、該当番号だけをレコードにします。通り名の JSON は JsonDocument で解析し、NativeAOT 用の reflection は不要です。番号の外向き表現は 7 桁の文字列、検索索引のみ固定桁の整数です。

`postal-codes.metadata.json` に形式の版、公式データ更新日、出典、元 ZIP と生成物の SHA-256、レコード数、分類件数を保存します。集計は日本郵便が定義した分類ではなく、本ツールの排他的な機械分類です。分類と安全に分離できるかの判定は別です。

## 更新と検証

提供元は [日本郵便の全国 UTF-8 データ](https://www.post.japanpost.jp/service/search/zipcode/download/utf-zip.html)。[使用・再配布・移植・改良について](https://www.post.japanpost.jp/service/search/zipcode/download/readme.html)には、郵便番号データの著作権を主張せず、自由な配布を認める旨が記載されています。詳細は THIRD-PARTY-NOTICES.md を参照してください。

Python 3.10 以降の標準ライブラリだけで生成できます。月ごとの公式更新を確認し、全国全件版から再生成します。実行時の自動ダウンロードは行いません。

```powershell
python tools/generate-postal-codes.py --input path/to/utf_ken_all.zip --source-date 2026-09-30 --report path/to/classification.json
# --input を省略した場合だけ、開発用ツールが公式サイトから取得します。
python tools/test_postal_generator.py
dotnet run --project src/Meltype.Core.Tests -- Postal
```

公式更新日は取得日と区別します。同じ ZIP と更新日からは、同じ辞書とメタデータを生成します。列数・文字コード・番号・制御文字・全国版としての件数を検証し、生成が成功してから書き換えます。辞書とメタデータを一緒にレビューし、アプリ更新に同梱します。

全国データの分類件数と代表例、分離できないケースは [POSTAL-DATA-ANALYSIS.md](POSTAL-DATA-ANALYSIS.md) を参照してください。将来の更新に未知の表記が加わった場合も、認識できるルールに一致しない住所を無理に短縮しません。
