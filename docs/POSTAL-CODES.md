# 郵便番号から住所への変換

日本郵便の一般住所データを同梱し、Windows・Mac・Linux 共通の Core で検索します。入力を外部サービスへ送信せず、オフラインで使用できます。

## 入力方法

Windows の動作モードが「Meltype IME」の場合は、試す入力欄で Win＋Space を押し、入力方式に「Meltype IME」を選んでから日本語入力にしてください。

日本語入力中に `1000001` または `100-0001` を入力して Space を押すと、番号を最初の候補に残したまま `東京都千代田区千代田` を住所候補に追加します。次の Space / ↓ または候補番号で選び、Enter で確定できます。入力中に Enter を押すと、番号のまま確定します。Esc で変換を取り消すと元の入力に戻ります。

Tab 変換を有効にした場合は Tab でも開けます。英語の文脈では従来どおり Space で番号を確定して空白を入れますが、Shift+Space で明示的に住所候補を開けます。直接入力・明示的な英数表示では住所変換しません。数字を使うかな入力の打鍵には適用しません。

検索対象は未確定入力全体が半角の 7 桁または `3 桁-4 桁` に一致する場合だけです。前後の空白・他の文字・任意の区切りを除去して検索することはありません。住所の一部からの逆引き、事業所個別番号、番地・建物名の補完は対象外です。

同じ番号に複数の住所が対応する場合は、全住所を候補に出します。「以下に掲載がない場合」などの説明は町名として入力せず、市区町村までの住所と注記に分けます。丁目・番地の範囲や階を含む町域の括弧は、意味を失わないよう住所文字列に保持し、「条件付き住所」の注記を付けます。必要な条件を確認して選んでください。

郵便番号から選んだ候補は、変換履歴・言語学習・予測変換の語句として保存しません。更新後に古い住所を学習結果として優先しないためです。通常の確定・診断ログの設定は従来どおりです。

## データと更新

- 提供元: [日本郵便・全国 UTF-8、1 レコード 1 行の住所データ](https://www.post.japanpost.jp/service/search/zipcode/download/utf-zip.html)
- 利用条件: [郵便番号データの説明](https://www.post.japanpost.jp/service/search/zipcode/download/readme.html)。「郵便番号データに限っては日本郵便株式会社は著作権を主張しません。自由に配布していただいて結構です。」
- 生成物: `dictionaries/postal-codes.tsv.gz` と `postal-codes.metadata.json`。元データの更新日・元 ZIP と生成物の SHA-256・件数を記録します。
- データは Core のリソースとして同梱し、起動時にバックグラウンドで UTF-8 本体と索引を準備し、全セッションで共有します。住所文字列は該当する番号の分だけ展開します。実行時にダウンロードしません。

月 1 回程度、公式ページの更新日を確認し、全国全件版から再生成します。差分の連続適用は不要です。Python 3.10 以降、標準ライブラリのみで動きます。

```powershell
# 全国 UTF-8 ZIP を保存してから再生成する場合
python tools/generate-postal-codes.py --input path/to/utf_ken_all.zip --source-date 2026-09-30

# 開発者が公式サイトから取得して再生成する場合 (このコマンドだけ通信する)
python tools/generate-postal-codes.py --source-date 2026-09-30

python tools/test_postal_generator.py
dotnet run --project src/Meltype.Core.Tests -- PostalCode
```

`--source-date` は公式の更新日に置き換えてください。取得日ではありません。取得日を生成物に含めないため、同じ ZIP・更新日からは同じファイルが生成されます。ダウンロードの失敗、ZIP/CSV の形式不正、空データや全国版として異常に少ない件数は、書き換える前にエラーになります。

再生成した 2 ファイルを一緒に変更管理し、住所・件数・ハッシュの差分を確認してからアプリを配布します。地域の変更は次のアプリ更新で反映されます。
